# 推送、同步与冲突恢复

在“同步与冲突”页查看工作目录、SDK 配置的远端端点、仓库身份和当前分支。
“准备推送”与“准备同步”只建立说明，点击“确认执行上述操作”才进行写操作；
取消准备不调用推送、同步或中止。换工作目录、分支或本地版本后需重新准备。

推送上传当前分支已有的本地提交，不自动提交 dirty 文件；固定关闭快进合并选项，不
强制覆盖远端。远端前进拒绝时，先核实结果、确认恢复标记，再明确同步，不自动重试。
离线提交与推送是独立操作。

同步使用 Lore 的正常分支语义，关闭 Reset/ForwardChanges，不传历史检出版本。
确认页的已核实远端版本是核实时间的状态，执行时分支可能有更新。首版采取保守预检：
dirty/staged/未完成合并均拒绝同步；物理文件（包括忽略文件）必须已纳入当前版本，
否则拒绝并指出路径。不会删除忽略/未跟踪文件；先将它们移出工作目录或明确纳入版本。
因此包含构建缓存、node_modules 等忽略内容的目录需先处理这些内容才能同步。
物理文件/目录和传入变更最多各核对 10,000 项，重解析点/链接与超限明确拒绝。
同时检查传入路径、目录替换和目录移除的内容；核对期间本地变化时停止。

本地未推送提交保留，分歧由 Lore 合并。调用返回成功也可能进入未完成冲突流程，
客户端按实际冲突/暂存状态显示，不把它称为已完成合并。已提交双父版本的第二父标识
不代表仍有冲突；需结合实际暂存版本与冲突文件判断。

冲突处理：选择文件，外部编辑当前工作文件，返回后点击“显式标记所选当前内容已解决”。
标记由 SDK 确认，客户端不替你选择本地或远端内容。全部解决后填写说明，点击
“继续合并并本地提交已暂存内容”；它提交当前所有已暂存内容，包括你另外暂存的文件。
完成后仍需明确准备并确认推送。未解决冲突会阻止继续、普通提交、同步与分支切换。

中止先点击“查看中止合并影响”，阅读说明再确认。Lore 中止会恢复当前本地已提交版本
对应内容，人工合并编辑可能被覆盖，已提交的本地版本保留；不能承诺恢复后端外部数据。
执行前将当前变更文件的原始字节备份到 `%TEMP%/SourceLore.AbortBackups/<随机目录>`，
`manifest.txt` 对应每个备份与工作路径，并记录原本不存在的文件。每文件最多 8 MiB、
总计 128 MiB、10,000 文件；备份失败不会调用中止。成功与失败产生的备份都保留，
不会自动恢复或删除它们。按提示手动核对需要保留的编辑；这些目录不是日志，不包含
客户端凭据，但可能包含你工作文件本身的敏感内容。

重启后重新扫描恢复冲突入口；未完成操作标记阻止普通写操作，不自动重放。
推送中断时，即使上传可能已经完成也显示结果待核实；确认恢复标记前再次核实远端，
网络或权限不足时保留标记与本地提交。同步/解决/中止失败先核对本地实际状态。
认证过期时保留工作与说明，明确登录，再核对标记并重新准备操作；当前真实受保护
浏览器认证验收尚未完成。客户端关闭等待原生调用结束，不以杀进程宣称已安全取消。

“核实远端状态”是明确联网操作。锚点按工作目录、仓库及分支隔离，只记录内存中的
最后成功核实版本与时间。失败保留旧锚点并标记过期、数量未知；离线本地提交后也显示
数量未知。后端确认本地版本已在远端历史时，基于该锚点显示 0，并注明不是实时状态。
有未推送提交时首版显示数量未知，不用版本号相减冒充 DAG 中的提交数。
