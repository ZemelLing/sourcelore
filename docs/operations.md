# 操作生命周期与恢复

每个 Lore 工作目录实例有独立串行调度器。扫描和状态核对也经过该通道；当前适配器不假定只读 SDK 调用可以安全并发。
会话按 SDK 实例身份去重，同一远端的不同克隆保留各自状态与提交草稿。

参数、回调和运行库必须存活到原生 END。取消排队中的操作不会取消已启动的调用；
查询代次失效只丢弃展示结果，不提前释放原生资源。应用退出前必须等待 `WhenIdleAsync` 后释放运行库。

未完成操作记录只包含实例、根路径、操作类型、起始版本和时间。使用生成的 JSON 元数据；不记录远端 URL、令牌、文件内容或提交说明。
记录先写临时文件，再原子替换。读取失败要提示需要核对，不能把坏记录当作“没有未完成操作”。

失败或重启后保留记录，从后端重新读取实际版本、分支和状态。记录不会触发自动重放。
结果确认之前禁止重复写操作；用户检查真实状态后才能明确清除标记并重试。
本地界面在打开/刷新后读取标记，显示开始与实际版本，阻止新写操作；用户检查后通过明确确认入口清除标记。
tracker 和持久化基础已有重启测试。远端写入的不确定结果仍需在同步任务中核对远端锚点，不能只凭本地版本判断推送结果。

原生文件日志关闭。应用显示诊断前清除 URL 查询参数、URL 凭据和常见 token/password/authorization 字段。
测试使用专门的测试秘密检查错误文本与恢复记录；不把原始 SDK 日志直接写入偏好文件。
