# SourceLore Windows x64 验收候选版

解压整个目录后运行 `SourceLore.App.exe`，不要只复制 exe。客户端使用 Avalonia 12、
编译绑定和 NativeAOT，运行目录带齐 Lore/渲染 DLL；客户端不调用 Git 或 Lore CLI。
干净系统上的依赖完整性仍待用户实测，不以开发机通过代替。

首次使用可打开已有 Lore 工作目录，或展开克隆入口，填写完整仓库地址及空目标目录。
明文服务用 `lore://主机:端口/仓库`，TLS 服务用 `lores://主机:端口/仓库`。
HTTP 健康检查地址不等于 Lore 仓库入口。连接失败保留残留路径，不自动覆盖或重试。
普通目录或只有 Git 元数据的目录不能当 Lore 工作目录。

工作区选择文件查看统一/并排差异，勾选与实际暂存状态独立。暂存后再编辑，提交采用
该路径的最新内容。填写说明后本地提交已暂存文件；推送需另行在同步页准备并确认。
历史可以选择主父、其他父或已加载版本比较同路径文件。基本分支创建从当前版本开始
并立即切换，不支持指定历史起点。详细步骤见随包的 `docs/`。

已实现并在本机构建机通过：变更查看、严格文本差异、暂存/提交、克隆、推送/同步、
历史比较、基础分支以及冲突解决/继续/中止。最新证据为 60 项检查及独立 AOT 双克隆
完整流程；测试服务器为隔离的 loreserver 0.10.0 匿名服务。

仍待验收：受保护服务的真实浏览器登录/取消/过期恢复、用户提供的外部服务器连接，
以及未安装 .NET/Git/Lore CLI 的干净 Windows x64 环境。以上不是已完成声明。
已验证系统仅 Windows 11 专业版 10.0.26200 x64，未据此宣称其他系统已通过。

主要限制：每侧文本 8 MiB/100,000 行/单行 100,000 UTF-16 字符；未知编码或二进制不
内置预览。同步保守拒绝包括忽略项在内的未跟踪物理文件、链接及超出 10,000 项的
风险核对。中止先备份（每文件 8 MiB，总计 128 MiB）；备份保留在提示的临时目录。
历史内容可能不在缓存，需要明确联网读取。数量未知不会显示成 0。资产专用功能未提供。

记录验收结果时请提供系统版本、启动与关键操作结果、依赖/连接错误文字；不要提供
密码或令牌。所有程序与许可文件的 SHA256 位于 `manifest.sha256`。
