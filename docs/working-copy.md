# 工作区、暂存和提交

打开目录进行一次完整扫描。随后合并 250 ms 内的文件事件，已知文件修改使用 SDK dirty
通知再核对状态；新增、删除、重命名、忽略规则变化和监控溢出执行扫描恢复。
Lore 决定有效路径、忽略规则及真实状态。客户端排除自身元数据事件，操作期间积累事件，
等待操作结束后核对。回到窗口及手动重新扫描也会恢复准确性。

列表分别显示磁盘 dirty、已暂存和冲突标记。勾选只选择批量操作的文件，不表示已经
暂存；点击暂存/取消暂存后，从后端刷新实际标记。即使某条路径失败，也不乐观地
修改整批标记。SDK 可能忽略不存在路径并返回成功，适配层还核对每条请求路径的实际状态，
报告未达成的路径。部分完成后保留实际列表和核对标记，检查后明确确认，不能自动重放。

暂存记录路径意图，不是冻结内容。已暂存文件继续编辑后，提交使用文件的最新内容；
取消暂存不恢复文件。文件级暂存支持新增/修改/删除，首版没有逐行暂存。

填写说明后，本地提交先扫描核对。空说明、没有已暂存文件、未处理冲突或待核实操作
都会阻止提交。只提交已暂存文件，保留其他修改，不隐含推送。
成功后清空说明并刷新版本/状态；失败或完成结果不确定时保留说明，显示实际版本和
核对入口，不自动再提交。

“工作区状态可能过期”表示扫描尚未完成或核对失败；此时旧列表只作为已知信息保留，
不能据此认定干净。状态核对包含部分错误时也拒绝显示为已完成。
