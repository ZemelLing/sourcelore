# 连接与认证恢复

匿名 Lore 服务可直接克隆，不必登录。展开连接入口，填写完整 Lore 仓库地址和
不存在或为空的目标目录，点击克隆并打开。非空目录不会覆盖；失败会保留残留目录，
检查后选新的空目标或自行处理。成功打开才加入最近记录；最近列表只保存本地根和名称。

受保护服务点击“登录此远端”，收到 SDK 登录地址后点击“打开登录浏览器”。
浏览器登录和凭据保存由 Lore 支持的认证机制管理，客户端不提供令牌输入框、不把登录
地址或令牌写入偏好、恢复标记及普通日志。打开浏览器只接受 HTTP/HTTPS。
SDK 原生日志关闭，展示的错误经脱敏。

成功后需明确重新发起失败的克隆或其他远端操作，不会自动重放。
失败或凭据过期也保留本地文件与草稿，重新登录后再明确重试。
“取消等待登录”停止客户端接收浏览器结果；固定 SDK 没有安全硬取消接口，底层调用
继续保持参数/句柄直到正常结束或超时。结束前操作入口保持互斥，窗口仍可显示和复制已有内容。
取消后也不自动执行远端操作；凭据是否已保存仍由 SDK 的实际认证流程决定。

受保护服务的真实登录/过期验收尚未完成。用户于 2026-10-13 补充测试服务器
`lore.inkarrays.com:41339`，该地址的 HTTP `/health_check` 已返回 200。
该服务的认证配置尚未通过 SDK 确认；健康检查成功不能证明克隆或认证可用。
已授权的测试仓库创建在固定 SDK 的 gRPC 连接阶段失败，详细证据和待排查项见
[外部测试服务器记录](external-server.md)。
当前已验证模拟认证事件的成功、失败、迟到成功、取消后的资源等待与不重放，以及匿名
服务器不提供认证端点的真实错误路径。这些不能替代真实受保护服务的浏览器认证验收。
