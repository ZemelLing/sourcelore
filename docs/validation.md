## 首个真实 NativeAOT 工作流

发布使用 `scripts/Publish-Windows.ps1`，无裁剪/AOT 警告，没有整体抑制分析。
`PublishedWorkflowTests` 启动完整发行目录中的 exe，不加载 App 托管程序集；程序确认不支持动态代码。

已通过：

- 中文及含空格临时 Lore 仓库的打开、初始扫描、真实 dirty/staged 列表。
- 300 行中文基线与修改内容的原生 patch；只读控件、行号、实际滚动偏移、选择、剪贴板复制及恢复原数据。
- 暂存、取消暂存、再次暂存后编辑、只提交选择的文件，未选内容保留。
- 空暂存提交阻止且草稿保留；带伪造目录标记的无效工作目录由 SDK 拒绝。
- 多次原生调用、回调数据复制、窗口响应与正常退出。
- 分别缺失和损坏 lorelib.dll 时显示修复提示并禁止仓库操作。
- 所有来源相同的文件元数据跨会话快速切换，旧差异不能覆盖新来源。

控件兼容处理均为本项目的小型适配，没有修改 NuGet 包：
`SourceText` 提供编译绑定；StyleKeyOverride 复用 TextEditor 主题模板。
进一步页面验证暴露 NativeAOT 下 OLE 剪贴板路径的不稳定读取/延迟数据问题，
Windows 复制改用 CF_UNICODETEXT：分配移动内存并在 SetClipboardData 成功后将所有权交给系统。
诊断从 GetClipboardData 独立读取，使用 OleDuplicateData 备份全部可复制格式，
不可保留的格式会在任何覆盖前拒绝测试；不以空文本替代原始数据。

Lore DLL 的 dumpbin 依赖检查只列出 Windows 系统 DLL，没有额外 VC 运行库依赖。
发行目录包含 Lore、Skia、HarfBuzz、ANGLE 原生库、第三方通知、许可元数据与清单。
