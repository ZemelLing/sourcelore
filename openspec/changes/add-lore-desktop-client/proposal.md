# Proposal

## Why

程序员需要通过独立桌面客户端完成 Lore 的日常代码版本管理：查看变更和文本差异、选择文件提交、同步远端、浏览历史以及管理基础分支。当前 sourcelore 仓库尚无应用实现；借鉴 SourceGit 的信息布局与操作习惯，并以 Lore 自身语义构建客户端，可以提供一致的开发工作流。

## What Changes

- 新建面向 Windows x64 的独立 Lore 客户端，采用 Avalonia 12、编译绑定和 NativeAOT；建议以 .NET 10 为目标框架。
- 提供打开本地 Lore 工作目录、克隆、最近使用记录和远端认证入口，以及仓库导航、工作区、历史和操作状态界面。
- 展示文件变更，支持自动刷新和手动扫描、文件级暂存/取消暂存、输入说明并本地提交；遵循 Lore 在提交时读取已暂存文件最新内容的语义。
- 提供工作文件与当前版本、历史文件与父版本之间的只读文本差异，支持统一和并排展示。
- 提供独立推送、同步和最低限度的冲突恢复流程，包括冲突列表、外部编辑后标记解决、继续及有明确语义的中止入口。
- 提供分页历史、提交详情和文件差异，以及分支列表、从当前版本创建并切换、切换已有分支。创建入口明确说明会改变当前分支；历史版本创建留待后续扩展。
- 将完整 Windows x64 发布产物的 NativeAOT 验证前置；验证 Lore 原生库加载、事件回调、文本差异展示和错误处理后再扩展完整工作流。
- 首版不包含 Git 后端、资产预览与锁管理、稀疏视图编辑、内置三方合并编辑器、按行/块暂存、跨平台发行、复杂历史改写、历史版本创建分支、仅创建不切换、分支删除/重命名或安装器/自动更新。

## Capabilities

### New Capabilities

- `desktop-runtime`: Windows x64 原生发布、Avalonia 12 编译绑定、原生依赖诊断和桌面交互基础。
- `repository-workspaces`: Lore 工作目录打开与克隆、会话切换、最近记录和认证生命周期。
- `working-copy`: 变更发现、文件级暂存和本地提交。
- `text-diff`: 工作区与历史版本的只读文本差异展示及非文本/大文件退化处理。
- `revision-history`: 分页历史、提交详情和本地未推送状态。
- `repository-sync`: 推送、同步、操作状态以及冲突恢复。
- `branch-management`: 分支列表、创建和保留本地工作的分支切换。

### Modified Capabilities

无。当前没有既有 capability 规格。

## Impact

- 在空白应用仓库中新增桌面 UI、应用服务、领域模型、Lore SDK 适配层及集成/发布验证；本变更当前阶段只产出规划文档。
- 主要依赖为 .NET 10、Avalonia 12、LoreVcs 与匹配的 `win-x64` 原生运行库；文本控件优先评估兼容 Avalonia 12 的 AvaloniaEdit。
- SourceGit 作为布局、交互和可审查的局部组件参考，不引入其 Git 命令层。实际复用源码时须保留相应许可声明。
- Lore 尚处于 1.0 之前，需要固定并验证 SDK、原生库和测试服务器的兼容组合；当前没有对 LoreVcs 或文本控件完成实际 NativeAOT 发布验证。
- 远端验证使用受控的本地/测试 Lore 服务器与临时仓库，不依赖用户的生产数据或 Unreal/UEFN 托管服务。
